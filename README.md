# World-Class App Developer Roadmap

> A 365-day, evidence-driven path from beginner to independent mobile product engineer, followed by a continuing path toward staff/principal engineer and founder/CTO capability.

[![Roadmap checks](https://github.com/alphasafal/world-class-app-developer-roadmap/actions/workflows/roadmap-check.yml/badge.svg)](https://github.com/alphasafal/world-class-app-developer-roadmap/actions/workflows/roadmap-check.yml)

## The honest target

No roadmap, certificate, or one-year schedule can guarantee “world best” or top 0.000001%. Principal engineers and CTOs are distinguished by years of difficult decisions, shipped systems, failures handled, teams influenced, and measurable user/business outcomes. This repository gives you the strongest controllable first year: 365 completed builds and a verified body of work. Continue the operating system after Day 365.

## Primary stack

- TypeScript + React Native + Expo for the fastest cross-platform product loop
- Swift + SwiftUI for genuine iOS depth
- Kotlin + Jetpack Compose for genuine Android depth
- Node.js + PostgreSQL for backend ownership
- GitHub Actions, Docker, OpenTelemetry, App Store Connect and Google Play for production operations

Do not learn Flutter in parallel during this year. After you can ship and defend the primary stack, build one comparative Flutter project.

## Start here

1. Read [Operating System](roadmap/OPERATING-SYSTEM.md).
2. Open [365-Day Roadmap](roadmap/365-DAYS.md).
3. Complete exactly one row per day; change only its checkbox from `[ ]` to `[x]`.
4. Copy [Daily Journal](templates/DAILY-JOURNAL.md) into `journal/day-XXX.md`.
5. Every seventh day, complete [Weekly Review](templates/WEEKLY-REVIEW.md).
6. Use [Assessment Rubric](roadmap/ASSESSMENT.md) before claiming a level.
7. Track credentials using [Certifications](roadmap/CERTIFICATIONS.md), but never substitute certificates for projects.

## Completion definition

A day counts only if:

- the intended behavior works from a clean setup;
- relevant tests pass;
- one failure or edge case is exercised;
- you can explain the critical code without AI;
- setup, evidence, limitations and next action are recorded;
- the work is committed with `day-XXX: concise outcome`.

Watching a course, copying a tutorial, or generating code that ran once does not count.

## Year-one gates

| Gate | Days | Observable capability |
|---|---:|---|
| Foundation | 1–56 | Build, debug, test and explain typed applications |
| Mobile product engineer | 57–196 | Ship accessible, secure, offline-capable React Native products |
| Native and systems engineer | 197–287 | Work deeply in Swift/iOS, Kotlin/Android, backend and distributed systems |
| Principal/founder apprenticeship | 288–365 | Lead architecture, reliability, strategy, product validation and a public capstone |

## Scoreboard

- Days completed: **0 / 365**
- Weekly reviews passed: **0 / 52**
- Production releases: **0 / 12 minimum**
- Store beta/public releases: **0 / 3 minimum**
- No-AI rebuilds: **0 / 52**
- User interviews: **0 / 30 minimum**
- Real users served: **0**
- Incidents/postmortems: **0 / 6 exercises**

Update this scoreboard only from linked evidence.
