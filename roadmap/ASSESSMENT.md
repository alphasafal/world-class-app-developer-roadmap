# Capability Assessment

Score each dimension from 0–4 using linked evidence: 0 none, 1 tutorial, 2 independent small system, 3 production evidence, 4 repeated production impact plus teaching/leadership.

| Dimension | Evidence |
|---|---|
| Programming and debugging | Independent implementations, failure diagnoses, complexity reasoning |
| Mobile UX and accessibility | Device matrix, screen-reader tests, design-system consistency |
| Native depth | Swift/iOS and Kotlin/Android applications plus one native module |
| Architecture | ADRs, modular boundaries, migrations and explicit tradeoffs |
| Data and distributed systems | Transactions, sync, idempotency, queues and resilience tests |
| Security and privacy | Threat models, MASVS review, secret handling and abuse cases |
| Performance | Reproducible profiles, budgets, traces and before/after metrics |
| Quality engineering | Unit/integration/E2E/contract tests and failure exercises |
| Delivery and operations | CI/CD, signing, staged rollout, telemetry, SLOs and rollback |
| Product judgment | Interviews, prioritisation, experiments and outcome metrics |
| Technical leadership | RFCs, reviews, mentoring, standards and conflict resolution |
| Business/CTO judgment | Cost, risk, hiring, compliance, roadmap and build-vs-buy decisions |

## Gates

- **Independent mobile engineer:** average ≥2; no zero; three polished apps; one store beta.
- **Senior-capability portfolio:** average ≥2.5; production evidence in quality, security and operations; meaningful user feedback.
- **Staff/principal apprenticeship:** average ≥3; one cross-team-style migration/platform project; architecture defense by experienced reviewers.
- **Founder/CTO apprenticeship:** average ≥3 plus a product with real users/revenue or a documented failed validation, operational plan, security/cost strategy and leadership evidence.

Passing this repository’s gate is not the same as holding a job title. External reviewers and real-world outcomes are mandatory.
